# Deploy or adapt an owned OpenVPN gateway

A configuration file is not management access. The supplied US-NewYork.ovpn points at a third-party VPN Gate/SoftEther endpoint, uses legacy AES-128-CBC/SHA1 and includes a shared dummy private key. It is excluded from APKs. Its presence does not verify ownership, uptime or US location. Do not upload private keys into the Admin's public-profile library.

The included package targets an authorized **Ubuntu 24.04** VPS with public IPv4, root rights, /dev/net/tun and valid public HTTPS DNS. Use a US-hosted provider if US egress is required; labels cannot change location. If your current server operator can install/adapt this authorization controller, that may be used instead. Otherwise an unmanaged public OVPN service cannot enforce your license revocations or per-customer credentials.

## Initial deployment

1. Create a disabled server draft in Admin, copy its generated gateway ID and align hostname/port/UDP-or-TCP/DNS/capacity with the intended actual VPS. DNS must point to that real IPv4. Do not invent an endpoint.
2. Review `install.sh` before running on the dedicated VPS. Copy VPN-Gateway there. Create root-owned `/etc/usa-favor/gateway.json` mode600 from gateway.example.json. Set the actual identity/hostname/egress IPv4 and a newly generated random management key (at least32 bytes entropy). Keep authorization_mode=firestore and firebase_project=usa-favor. The legacy root bearer control key stays on the server; Android admin operations use Firebase ID tokens.
3. Configure Firebase Admin SDK ADC on the VPS. The systemd unit expects `GOOGLE_APPLICATION_CREDENTIALS=/etc/usa-favor/service-account.json`; supply a dedicated project service account there, root-owned mode600, never in APK/Git/Firestore/chat. Grant least required Firestore document read/write and Firebase Auth user read privileges for check_revoked; e.g. roles/datastore.user and roles/firebaseauth.viewer on usa-favor, reviewed for your environment. Use workload identity when supported instead of a long-lived file, adjusting the unit accordingly. This trusted identity can bypass rules and must be protected. No Secret Manager or Cloud Functions deployment is required for this mode.
4. Run `sudo bash install.sh`. It installs OpenVPN/EasyRSA, the authorization agent in its own Python venv with firebase-admin==7.1.0, a per-session issuer, CRL, nftables routing/guards, nginx and systemd. It does not flush existing firewall tables or SSH policy. Enable the actual UDP/TCP VPN port,443 and ACME port80 at provider/UFW as appropriate. Do not run the VPS installer inside a developer container.
5. Obtain/renew public TLS with `sudo certbot --nginx -d YOUR_ACTUAL_DOMAIN --redirect`. Verify DNS, nginx and renewal. Agent9080 binds loopback. Root-only CA/server keys, management key and service account stay on this VPS. Protect encrypted issuer backups and synchronize the clock.
6. Inspect `systemctl status usa-favor-agent openvpn-server@usa-favor usa-favor-firewall`, `nginx -t` and redacted logs. In Admin, save, enable, TEST and PUBLISH. Gateway health must verify identity, OpenVPN and configuration before publication. An imported safe public profile can populate a draft but never provides these management rights.

## Remote controls

Compatible registered servers can be renamed, reordered, assigned primary/backup, enabled/disabled or put in maintenance from Admin. Supported port/transport/DNS/capacity changes require configure → test → publish, appropriate real firewall changes and may interrupt sessions. Moving IP/domain requires real DNS/HTTPS/VPS changes too. The rotate operation rotates the tls-crypt-v2 wrapping key and restarts OpenVPN; full CA/service-account/control-key rotation requires infrastructure work. Removal unregisters a gateway, not cancellation of hosting.

Revocation/expiry/reset/maintenance are rechecked at the gateway, including established sessions. Firestore authorization cache is at most45s and the enforcement sweep runs every15s plus network/load delays. A service outage denies authorization once valid cache expires. Sessions are random-token authenticated, max1h bounded by paid expiry, with per-session certificates and revocation. One new session replaces the prior session lock for that license; termination on another gateway follows its next check.

## Required acceptance — not performed in this workspace

On your actual VPS and a physical Android device, verify unauthenticated control denial; a valid test license; real VPN permission/service/tunnel; HTTPS egress-IP equality; DNS and IPv6 leak blocking; no private/LAN/metadata reachability; byte counters; Wi-Fi/mobile changes; process recreation; disconnect; revoke/expire/reset while connected; controller outage fail-closed; reboot/firewall/renewal; and a second server/config change without rebuilding the Client. Record actual host location, OS/device, timestamps and revocation latency. Source/unit tests and APK builds do not prove these operating results.
